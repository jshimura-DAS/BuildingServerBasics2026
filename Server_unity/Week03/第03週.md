## 1. Flaskとは
Flaskは、Pythonで書かれた**軽量なWebフレームワーク**で、数行のコードでWebサーバー機能を持つプログラムを作成可能。

- 必要最小限の機能だけを持ち、必要に応じて拡張する設計（マイクロフレームワーク）。
- URLと関数を対応付けるだけで、Webページ・Web APIを作成できる。

第04週以降で、第02週で学んだ辞書をJSONとして返すWeb APIに発展させる想定。

### Webフレームワークとは
Webサーバー開発で共通して必要な処理（リクエストの受け取り、URLごとの振り分け、レスポンスの返却）を部品としてまとめたもので、自前で通信処理を書かずに、「どのURLで何を返すか」に集中できる特長を持つ。

## 2. Flask と PHP + Apache の違い
Webサーバーを作る方法は複数ある。代表的なPHP + ApacheとFlaskを比較する。

| 項目 | PHP + Apache | Python + Flask |
| ---- | ------------ | -------------- |
| 言語 | PHP | Python |
| Webサーバーの役割 | Apacheが常時稼働し、リクエストを受けてPHPを呼び出す | Pythonプログラム自身がサーバーとして待ち受ける（開発用サーバー） |
| URLの決まり方 | ファイルの置き場所（`/var/www/html/index.php`など） | コード上のルーティング（`@app.route`） |
| 1リクエストの流れ | Apache → PHP処理 → 応答 | Flask（Python関数）→ 応答 |
| 設定 | Apacheの設定ファイルが必要 | Pythonコードのみで開始できる |
| 得意分野 | 従来型のWebページ配信 | Web API、Pythonのデータ処理との連携 |

要点のまとめ：
- PHP + Apacheは、**ファイルを置くとURLになる**
- Flaskは、**関数とURLをコードで対応付ける**
- 本講座では、ゲーム（Unity）から呼び出すAPIを作るのが主な目的であるため、Flaskを採用する。
### 補足: 開発用サーバーと本番運用
Flaskに内蔵されている開発用サーバーは、学習・動作確認用。本番運用では、ApacheやNginxなどのWebサーバーと組み合わせて公開するのが一般的で、Flaskと排他的な関係ではない。本講座では開発用サーバーのみ使う。

### 手順(3)：最小のFlaskアプリを作成
`~/class_python/app.py`を作成し、以下を保存する。

```python
# app.py
from flask import Flask

app = Flask(__name__)


@app.route("/")
def hello():
	return "Hello World"


if __name__ == "__main__":
	app.run(host="0.0.0.0", port=5000, debug=True)
```

コードの意味:
- `Flask(__name__)`: Flaskアプリ本体を作る。
- `@app.route("/")`: URL`/`にアクセスされたとき、直下の関数を実行する（**ルーティング**）。
- `return "Hello World"`: ブラウザに返す内容。
- `host="0.0.0.0"`: 仮想マシン外（Windows側）からの接続も受け付ける指定。仮想マシン内だけで使う場合は`127.0.0.1`でよい。
- `port=5000`: 待ち受けるポート番号。
- `debug=True`: 開発用の設定。コード変更時の自動再起動とエラー詳細表示を有効にする。学習用であり、公開環境では使わない。

#### 補足: `if __name__ == "__main__":` の意味

Pythonにおいて、このパターンは**エントリーポイント（プログラムの開始点）を指定する手法**です。C#やJavaでの`Main`メソッドに相当します。

**ダブルアンダーバー（`__`）の意味:**

`__` で囲まれた名前は、Pythonの **特殊変数（special variable / magic variable）** を表します。言語が自動的に設定する変数で、プログラマが通常は手動で代入しません。
例：
- `__name__`: 実行中のモジュール名
- `__file__`: ファイルパス
- `__doc__`: ドキュメント文字列

**`__name__` の値:**

- このファイルを直接実行した場合: `__name__ == "__main__"` （文字列の値が`"__main__"`）
- このファイルが別ファイルから読み込まれた（import された）場合: `__name__` はモジュール名（例：`"app"`）

**なぜこの書き方をするのか:**

```python
# app.py の内容
from flask import Flask

app = Flask(__name__)

@app.route("/")
def hello():
    return "Hello World"

# このブロックは、app.py が直接実行される場合だけ動作する
if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000, debug=True)
```

**実行例:**

ケース1: `app.py`を直接実行
```bash
python3 app.py
```
→ `__name__` は `"__main__"` となり、`if`ブロック内のコードが実行される。Flaskサーバーが起動。

ケース2: 別ファイル（例：`server.py`）から`app.py`を読み込む
```python
# server.py
from app import app

# ここで app.py を import した場合、app.py 内の __name__ は "app" となり、
# if __name__ == "__main__": ブロックは実行されない。
# つまり、Flaskサーバーは勝手に起動しない。
```

**実践的なメリット:**

- **テストやモジュール化に対応**: `app.py`を他ファイルから読み込むときに、自動起動を避けられる。
- **意図的な開始**: プログラム実行の明確な開始地点を示せる。
- **標準パターン**: Pythonプログラムの一般的な書き方として、コードの可読性も向上。

**簡潔な書き換え例:**

今回の例では、`app.run()`を直接関数化することで、他ファイルからも制御可能にできます。

```python
def run_server():
    app.run(host="0.0.0.0", port=5000, debug=True)

if __name__ == "__main__":
    run_server()
```

この場合、別ファイルから`app.py`を読み込んでも、`run_server()`は勝手には呼ばれず、明示的に呼び出すときだけ実行されます。

**C#との比較:**

| 項目 | Python | C# |
| ---- | ------ | ---- |
| エントリーポイント指定 | `if __name__ == "__main__":` | `static void Main()` |
| 特殊変数の表記 | `__name__` | なし（`Main`は予約語） |
| 実行可否の判定 | 文字列比較 | メソッドシグネチャで指定 |
| モジュール読み込み時 | `__name__`は別の値 | `Main`は呼ばれない |

### 手順(4)：ファイアウォール設定（重要）
Ubuntuのファイアウォール（ufw）が有効な場合、ポート5000がブロックされている可能性がある。Flask起動前に確認・許可する。

**ファイアウォール状態の確認:**

```bash
sudo ufw status
```

結果が`inactive`なら、ファイアウォールは無効のため、このステップはスキップできる。

結果が`active`なら、ポート5000を許可する：

```bash
sudo ufw allow 5000/tcp
sudo ufw status
```

実行後、以下のように5000/tcpが`ALLOW`と表示されることを確認する：

```text
5000/tcp                   ALLOW       Anywhere
```

**補足:**
このステップでファイアウォール設定が完了する。以降のFlask起動時には、改めてこの設定を実行する必要はない。

## トラブルシューティング: ブラウザから接続できない場合

ブリッジアダプター環境でFlaskが起動しても、Windowsブラウザから応答がない場合は、以下を順に確認する。

### 段階1: Flaskが本当に起動しているか確認

仮想マシン内で、別のターミナルを開いて実行。

```bash
curl http://127.0.0.1:5000/
```

`Hello World`と返ってくれば、Flaskは正常に起動している。返らなければ、Flaskプロセスが落ちていないか確認する。

```bash
ps aux | grep python3
```

### 段階2: ポート5000が本当に待ち受けているか確認

```bash
sudo netstat -tlnp | grep 5000
```

または

```bash
sudo ss -tlnp | grep 5000
```

結果に `5000` と `python3` が表示されれば、正常に待ち受けている。表示されない場合は、Flaskアプリのエラーを確認する（手順3）。

### 段階3: Flaskアプリケーションのエラーログを詳しく見る

Flaskの`debug=True`は有効だが、エラーがある場合は詳しく出力するよう設定する。`app.py`を次のように修正：

```python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def hello():
    return "Hello World"

if __name__ == "__main__":
    try:
        app.run(host="0.0.0.0", port=5000, debug=True)
    except Exception as e:
        print("エラー:", e)
```

再度`python3 app.py`を実行し、エラーメッセージを確認する。

### 段階4: Ubuntuのファイアウォール設定

Ubuntuが有効にしているファイアウォール（ufw）がポート5000をブロックしている可能性。

```bash
sudo ufw status
```

有効（active）の場合、5000番ポートを許可する：

```bash
sudo ufw allow 5000/tcp
sudo ufw status
```

再度ブラウザで`http://172.25.21.149:5000/`にアクセスを試す。

### 段階5: Windowsファイアウォール設定

Windows側のファイアウォールがUbuntuへのアクセスをブロックしている可能性。

1. Windows「設定」→「プライバシーとセキュリティ」→「Windows ファイアウォール」。
2. 「ファイアウォールを通すアプリを許可」を確認。
3. 必要に応じて、Python関連のアプリをチェックして許可する。

### 段階6: IPアドレスとポート番号の再確認

仮想マシンでFlask起動時に表示されるIPアドレスを正確に確認。

```bash
hostname -I
```

そのIPアドレスとポート5000を組み合わせてブラウザに入力。例：`http://172.25.21.149:5000/`

Windows側でも、接続先のアドレスが正しいか確認。URLをコピー&ペーストする方が誤入力を防げる。

### 段階7: ネットワーク接続の確認

Windows からUbuntuへ通信できるか確認。Windowsのコマンドプロンプトか PowerShell で实行：

```powershell
ping 172.25.21.149
```

応答（Reply）が返ってくれば、ネットワーク接続は問題ない。返らない場合は、ネットワーク設定に問題がある可能性。

### よくある原因と対策

| 症状 | 原因 | 対策 |
| ---- | ---- | ---- |
| `curl` は成功するが、ブラウザから接続できない | Ubuntuファイアウォール | `sudo ufw allow 5000/tcp` |
| `curl` も失敗する | Flaskプロセスが起動していない | `python3 app.py`を実行 |
| `ping` も返らない | ネットワーク接続自体の問題 | VirtualBoxのネットワーク設定を確認 |
| ブラウザに「接続がリセットされました」と表示 | Windowsファイアウォール | Windowsファイアウォール設定を確認 |

### 最終確認：テストスクリプト

トラブルシューティングをまとめるため、仮想マシン内で以下のスクリプトを実行して、環境の状態を一括確認できるようにする。

```bash
#!/bin/bash
echo "=== Python バージョン ==="
python3 --version

echo "=== Flask インストール確認 ==="
python3 -c "import flask; print('Flask:', flask.__version__)"

echo "=== ポート5000の使用状況 ==="
sudo ss -tlnp | grep 5000 || echo "ポート5000は使用されていません"

echo "=== ファイアウォール状態 ==="
sudo ufw status

echo "=== ローカルIPアドレス ==="
hostname -I
```

このスクリプトを`check_env.sh`として保存し、実行権限を付与してから実行：

```bash
chmod +x check_env.sh
./check_env.sh
```

出力から、環境がFlask実行に必要な設定になっているか確認できる。

## 4. ルーティングの基本
flaskではPythonのコードによって、URLごとに別の関数を割り当てる。指定されたURLにアクセスすると、対応する関数が実行される。以下のコードでは、３つのルーティングを追加している。

```python
# app_routing.py
from flask import Flask

app = Flask(__name__)


@app.route("/")
def index():
	return "Hello World"


@app.route("/about")
def about():
	return "これはFlask学習用のサーバーです"


@app.route("/hello/<name>")
def hello_name(name):
	return f"Hello, {name}!"


if __name__ == "__main__":
	app.run(host="0.0.0.0", port=5000, debug=True)
```

動作確認:

| URL | 表示 |
| --- | ---- |
| `http://127.0.0.1:5000/` | Hello World |
| `http://127.0.0.1:5000/about` | これはFlask学習用のサーバーです |
| `http://127.0.0.1:5000/hello/Taro` | Hello, Taro! |

- `<name>`のように書くと、URLの一部を関数の引数として受け取れる。
- 存在しないURLにアクセスすると、Flaskが自動的に`404 Not Found`を返す。

## 5. 第02週との接続: 辞書を使った表示
第02週で学んだ辞書・リストを使い、サーバー側のデータからページを生成する。

```python
# app_dict.py
from flask import Flask

app = Flask(__name__)

players = [
	{"name": "A", "score": 950},
	{"name": "B", "score": 1330},
	{"name": "C", "score": 1210},
]


@app.route("/ranking")
def ranking():
	sorted_players = sorted(players, key=lambda p: p["score"], reverse=True)
	lines = []
	for i, p in enumerate(sorted_players, start=1):
		lines.append(f"{i}位 {p['name']} : {p['score']}")
	return "<br>".join(lines)


if __name__ == "__main__":
	app.run(host="0.0.0.0", port=5000, debug=True)
```

`http://127.0.0.1:5000/ranking`にアクセスし、スコア順の一覧が表示されることを確認する。

ここでは文字列（HTML）として返している。**辞書をJSON形式で返すWeb API**は、第04週で学ぶ。
