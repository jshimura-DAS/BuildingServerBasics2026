### 1. 単一ファイル保存とデータベースの違い

#### 1-1. 単一ファイル（JSONなど）で保存する場合
`players.json`のように、データ全体を1つのファイルに書き出す方法である。

- 全件を読み込んでからPythonで検索・並び替えを行う。
- 1件を更新する場合でも、ファイル全体を書き直す必要がある。
- 複数のプログラムが同時に書き込むと、データが壊れる危険がある。

#### 1-2. データベースで保存する場合
データを「テーブル」という表で管理し、SQL（データベースへの命令文）で操作する。

- 必要なデータだけを条件指定して取得できる（例: スコアが1000以上のプレイヤー）。
- 1件だけを更新・削除できる。
- 型（整数・文字列など）や必須項目などの制約を設定できる。
- 書き込みはトランザクションとして扱われ、途中で失敗してもデータの整合性を保ちやすい。
- データ件数が増えても、検索の仕組みを利用して効率よく取り出せる。

#### 1-3. 比較表

| 観点 | 単一ファイル（JSON） | データベース（SQLite） |
| ---- | ---- | ---- |
| 保存単位 | ファイル全体 | テーブル内の1行ずつ |
| 検索 | Pythonで全件を走査 | SQLで条件指定して取得 |
| 1件の更新 | ファイル全体を書き直す | 対象の行だけを更新 |
| 型・制約 | 制約なし（自分で検査） | 型や必須項目を指定可能 |
| 同時アクセス | 壊れやすい | 整合性を保つ仕組みがある |
| データ量の増加 | 読み書きが遅くなりやすい | 検索の仕組みで対応しやすい |
| 向いている用途 | 少量の設定データ | ランキング、ユーザー情報など |

#### 1-4. データベースを利用するメリット
- **検索が簡単で速い**: 「スコア上位10人」といった問い合わせをSQL1行で書ける。
- **更新が安全**: 1件ずつ変更でき、途中で失敗した場合は変更を取り消せる。
- **構造を守れる**: 名前は必須、スコアは整数といった決まりをデータベース側で強制できる。
- **将来の拡張に強い**: 第06週以降のAPIや第09週のランキング機能で、そのまま利用できる。

### 2. SQLiteとは

#### 2-1. 位置づけ
SQLiteは、データベースの機能を1つのファイルで提供する軽量なデータベースエンジンである。
MySQLやPostgreSQLのような**データベースサーバー**を別途起動する必要がなく、Pythonの標準ライブラリ`sqlite3`からそのまま利用できる。

#### 2-2. 概要と解説
- データベース本体は1つのファイル（例: `game.db`）として保存される。
- サーバーの設定やユーザー管理が不要で、学習や小規模なアプリケーションに適している。
- データ操作はSQL（Structured Query Language）で記述する。
- SQLiteは多くのスマートフォンアプリや組み込み機器でも利用されている。

#### 2-3. 他のデータベースとの違い

| 項目 | SQLite | MySQL / PostgreSQL |
| ---- | ---- | ---- |
| 形態 | ファイル1つ | データベースサーバーが必要 |
| 導入 | 不要（標準ライブラリ） | サーバーのインストールと設定が必要 |
| 同時書き込み | 得意ではない（小規模向け） | 多数の利用者に対応しやすい |
| 向いている場面 | 学習、開発、小規模アプリ | 大規模な公開サービス |

### 4. Pythonからの利用開始

SQLiteを使う基本の流れは次のとおりである。

1. `sqlite3.connect()`でデータベースに接続する（ファイルがなければ自動作成される）。
2. `cursor`または`conn.execute()`でSQL文を実行する。
3. 変更を保存するために`commit()`を実行する。
4. 利用が終わったら`close()`で接続を閉じる。

```python
# sqlite_hello.py
import sqlite3

conn = sqlite3.connect("game.db")
cursor = conn.cursor()

cursor.execute("SELECT sqlite_version()")
print(cursor.fetchone())

conn.close()
```

---

### 5. 設定に関する解説

#### 5-1. connect()の主な引数

| 指定 | 意味 |
| ---- | ---- |
| `"game.db"` | 使用するデータベースファイルのパス |
| `":memory:"` | メモリ上のデータベース（終了すると消える） |
| `timeout=5` | ロックされている場合に待つ秒数 |

#### 5-2. よく使う設定

```python
conn = sqlite3.connect("game.db", timeout=5)
conn.row_factory = sqlite3.Row
conn.execute("PRAGMA foreign_keys = ON")
```

- `row_factory = sqlite3.Row`: 結果を`row["name"]`のように列名で取り出せる。
- `PRAGMA foreign_keys = ON`: 外部キー制約を有効にする。接続ごとに設定が必要である。
- `timeout`: 別の処理が書き込み中の場合に、すぐエラーにせず待つ時間を指定する。

#### 5-3. コミットについて
データの追加・更新・削除は、`commit()`を実行するまで確定しない。
`with sqlite3.connect(...) as conn:`を使うと、ブロックが正常終了したときに自動で`commit()`が実行される。ただし、この書き方では接続は閉じられないため、必要に応じて`close()`を実行する。

### 6. 簡単なデータの保存と問い合わせ

#### SQLとは
SQL（Structured Query Language）は、データベースに対して「データを作る」「追加する」「取り出す」「変更する」「削除する」などの命令を書くための言語である。
SQLで書いた命令文を**SQL文**と呼ぶ。SQLiteを含む多くのデータベースで共通して使える。

#### SQLiteでのSQL文の指定方法
PythonのSQL文は、文字列としてSQLiteに渡す。

- SQL文は`cursor.execute()`の第1引数に文字列として書く。
- SQL文の中で値を使うときは、`?`（プレースホルダー）を書き、値は第2引数のタプルで渡す。
- 複数行にわたるSQL文は、三重引用符`"""`で囲むと読みやすく書ける。
- SQL文の末尾の`;`（セミコロン）は、1つの`execute()`で1文だけ実行する場合は省略できる。
- SQLの予約語（`SELECT`、`INSERT`など）は大文字・小文字を区別しない。ただし、読みやすさのため大文字で書くことが多い。
- `execute()`では複数のSQL文を同時に実行できない。複数文をまとめて実行する場合は`executescript()`を使う。

#### SQL構文の例

```sql
-- テーブルの作成（--以降はコメント）
CREATE TABLE IF NOT EXISTS players (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    score INTEGER NOT NULL
);

-- データの追加
INSERT INTO players (name, score) VALUES ('PlayerA', 1250);

-- データの取得（条件・並び順・件数の指定）
SELECT name, score
FROM players
WHERE score >= 1000
ORDER BY score DESC
LIMIT 5;

-- データの更新
UPDATE players SET score = 1400 WHERE name = 'PlayerA';

-- データの削除
DELETE FROM players WHERE name = 'PlayerC';
```

#### 6-1. テーブルの作成

```python
cursor.execute("""
	CREATE TABLE IF NOT EXISTS players (
		id INTEGER PRIMARY KEY AUTOINCREMENT,
		name TEXT NOT NULL,
		score INTEGER NOT NULL
	)
""")
```

#### 6-1の解説
6-1では、`players`テーブルを作成するSQL文を`cursor.execute()`で実行している。

| 要素 | 意味 |
| ---- | ---- |
| `cursor.execute()` | SQL文をSQLiteに送って実行するメソッド |
| `"""..."""` | 複数行のSQL文を1つの文字列として書くための書き方 |
| `CREATE TABLE` | 新しいテーブル（表）を作成する命令 |
| `IF NOT EXISTS` | 同名のテーブルが既にある場合は、作成せずにエラーも出さない指定 |
| `players` | 作成するテーブルの名前 |
| `id INTEGER PRIMARY KEY AUTOINCREMENT` | 行を識別する整数の列。行を追加するたびに値が自動で1ずつ増える |
| `name TEXT NOT NULL` | 文字列（TEXT）を入れる列。空（NULL）の登録を禁止する |
| `score INTEGER NOT NULL` | 整数（INTEGER）を入れる列。空（NULL）の登録を禁止する |

- `CREATE TABLE`の後の`(`から`)`の中に、列名と型、制約を並べる。
- 列の定義はカンマ`,`で区切る。最後の列定義の後ろにはカンマを付けない（第04週のJSONと同じ注意点）。
- `PRIMARY KEY`は、行を一意に識別するための列であり、同じ値の行は登録できない。
- `AUTOINCREMENT`を指定すると、`id`の値を指定しなくても自動で番号が付く。

主なデータ型は次のとおりである。

| 型 | 内容 | 例 |
| ---- | ---- | ---- |
| `INTEGER` | 整数 | `1250` |
| `REAL` | 小数 | `3.14` |
| `TEXT` | 文字列 | `'PlayerA'` |
| `BLOB` | バイナリデータ | 画像などのデータ |
| `NULL` | 値がないこと | 空の値 |

SQLiteは列の型をある程度柔軟に扱うが、本授業では上の型を基本として使う。

#### 6-2. データの追加（プレースホルダー）

```python
cursor.execute(
	"INSERT INTO players (name, score) VALUES (?, ?)",
	("PlayerA", 1250),
)
conn.commit()
```

値の部分に`?`を書き、値を別の引数で渡す。
文字列を直接組み立てると、SQLインジェクションと呼ばれる危険があるため、必ず`?`を使う。

#### 6-3. データの取得

```python
cursor.execute("SELECT id, name, score FROM players WHERE score >= ?", (1000,))
rows = cursor.fetchall()
```

- `fetchone()`: 1件だけ取得する。
- `fetchall()`: 条件に合う全件をリストで取得する。

#### 6-4. データの更新と削除

```python
cursor.execute("UPDATE players SET score = ? WHERE name = ?", (1400, "PlayerA"))
cursor.execute("DELETE FROM players WHERE name = ?", ("PlayerC",))
conn.commit()
```

### 7. 主なSQL文の意味

| SQL文 | 意味 |
| ---- | ---- |
| `CREATE TABLE` | テーブル（データを入れる表）を作成する |
| `IF NOT EXISTS` | 既にテーブルがあれば作成しない（エラーを防ぐ） |
| `INSERT INTO ... VALUES` | 表に新しい行を追加する |
| `SELECT 列名 FROM テーブル` | 指定した列を取り出す |
| `WHERE` | 条件に合う行だけを対象にする |
| `ORDER BY score DESC` | スコアの高い順に並べる（`DESC`は降順） |
| `LIMIT 3` | 先頭から3件だけを取り出す |
| `UPDATE ... SET ... WHERE` | 条件に合う行の値を変更する |
| `DELETE FROM ... WHERE` | 条件に合う行を削除する |
| `PRIMARY KEY` | 行を一意に識別する列（重複不可） |
| `AUTOINCREMENT` | 行を追加するたびに番号を自動で増やす |
| `NOT NULL` | 空の値を許可しない |

※ `WHERE`を省略したUPDATEやDELETEは、すべての行に対して実行されるため注意する。

### 8. プレイヤーデータの保存例

次のプログラムは、`players`テーブルを作成し、プレイヤーを登録して、スコア上位3人を表示する。

```python
# sqlite_player_sample.py
import sqlite3

DB_PATH = "game.db"

conn = sqlite3.connect(DB_PATH)
cursor = conn.cursor()

cursor.execute("""
	CREATE TABLE IF NOT EXISTS players (
		id INTEGER PRIMARY KEY AUTOINCREMENT,
		name TEXT NOT NULL,
		score INTEGER NOT NULL
	)
""")

cursor.execute(
	"INSERT INTO players (name, score) VALUES (?, ?)",
	("PlayerA", 1250),
)
cursor.executemany(
	"INSERT INTO players (name, score) VALUES (?, ?)",
	[("PlayerB", 1330), ("PlayerC", 980)],
)
conn.commit()

cursor.execute(
	"SELECT name, score FROM players ORDER BY score DESC LIMIT 3"
)
for rank, (name, score) in enumerate(cursor.fetchall(), start=1):
	print(f"{rank}位: {name} ({score}点)")

conn.close()
```

- このプログラムを複数回実行すると、同じプレイヤーが何度も登録される。やり直す場合は`game.db`を削除する。
- `executemany()`は、同じSQL文に複数の値の組を一度に渡す場合に使う。
- `enumerate(..., start=1)`で順位を1から数えている。
