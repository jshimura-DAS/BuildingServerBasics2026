## スコア登録APIの作成（Flask × SQLite）

第03週でFlaskの基本、第04週でJSON、第05週でSQLiteによるデータ保存を学んだ。今週はこれらを統合し、Unity等の外部クライアントからPOSTされたプレイヤー名・スコアを受け取り、JSONをパースしてSQLiteへ保存するAPIを作成する。

---

### 1. APIとは何か

#### 1-1. 定義
API（Application Programming Interface）は、あるプログラムが別のプログラムに対して機能を提供するための窓口である。
Web APIは、HTTP通信を使ってサーバーの機能をクライアント（Unityなど）に提供するAPIである。

#### 1-2. これまでの学習との関係
- 第03週: `GET`でルーティングを設定し、文字列やJSONを返すAPIを作成した。
- 第04週: 辞書をJSONに変換し、レスポンスとして返した。
- 第05週: SQLiteにデータを保存・取得する方法を学んだ。
- 第06週: クライアントから**データを送ってもらい（POST）**、サーバー側で検証してSQLiteに保存する。

#### 1-3. GETとPOSTの違い

| 観点 | GET | POST |
| ---- | --- | ---- |
| 主な用途 | データの取得 | データの送信・登録 |
| データの位置 | URL（クエリパラメータ） | リクエストボディ |
| 今回の用途 | ランキングの取得（第09週） | スコアの登録（今回） |

---

### 2. API設計に関する注意事項

APIは一度公開すると、クライアント側（Unity）のコードと密接に結びつくため、後から変更しにくい。設計段階で次の点に注意する。

- **エンドポイント名は役割が分かる名前にする**（例: `/api/scores`）。
- **リクエストとレスポンスの形式を先に決める**。実装より先に仕様を文書化する。
- **サーバー側では、送られてきたデータを信用しない**。型・範囲・必須項目を必ず検証する。
- **成功時と失敗時で、HTTPステータスコードを使い分ける**（詳細は4章）。
- **エラーの内容をクライアントが理解できる形で返す**。原因が分かるメッセージを添える。
- **1つのAPIには1つの責務を持たせる**。スコア登録とランキング取得は別のエンドポイントにする。

### 4. 仕様で確定すべき項目

API実装の前に、受け取るデータの仕様を表として明確にしておく。仕様があいまいだと、不正データの判定基準が実装者によってばらつくためである。

| 項目名 | 型 | 必須 | 範囲・制約 | 備考 |
| ---- | ---- | ---- | ---- | ---- |
| `name` | 文字列（str） | 必須 | 1〜20文字、前後の空白は不可 | プレイヤー名 |
| `score` | 整数（int） | 必須 | 0以上999999以下 | 負の値・小数は不可 |

#### 4-1. 補足事項
- `name`は空文字列（`""`）や、空白のみの文字列（`"   "`）を許可しない。
- `score`は`True`や`"100"`のような、整数以外の型を許可しない（Pythonでは`bool`が`int`の仲間として扱われる点に注意する）。
- JSON自体の形式が壊れている場合（パース不可）も、エラーとして扱う。

#### 4-2. HTTPステータスコードの使い分け

| ステータスコード | 意味 | 使用する場面 |
| ---- | ---- | ---- |
| `200 OK` | 正常終了 | スコア登録が成功したとき |
| `201 Created` | 新規作成の成功 | 新しいレコードを作成できたとき（今回はこちらを使う） |
| `400 Bad Request` | クライアント側のデータ不備 | 必須項目がない、型が違う、範囲外など |
| `415 Unsupported Media Type` | 形式の誤り | `Content-Type`がJSONでない |
| `500 Internal Server Error` | サーバー側の予期しないエラー | プログラムの不具合など |

### 5. 不適切なデータへの対処方法の検討と策定

#### 5-1. 想定される不正データ

| ケース | 例 | 対処 |
| ---- | ---- | ---- |
| JSONの形式が壊れている | ボディが空、カンマ不足 | `400`で「JSONの形式が不正です」 |
| 必須項目の欠落 | `name`がない | `400`で「nameは必須です」 |
| 型の誤り | `score`が文字列`"abc"` | `400`で「scoreは整数で指定してください」 |
| 範囲外の値 | `score`が`-10`や`10000000` | `400`で「scoreは0〜999999の範囲で指定してください」 |
| 文字数超過 | `name`が21文字以上 | `400`で「nameは20文字以内で指定してください」 |
| 空白のみの名前 | `name`が`"   "` | `400`で「nameに有効な文字を入力してください」 |

#### 5-2. 検証の順序
検証は次の順序で行うと、原因を特定しやすい。

1. JSONとして読み込めるか（パース可否）。
2. 必須項目（`name`, `score`）が存在するか。
3. それぞれの型が正しいか。
4. 値が範囲・文字数の条件を満たすか。

途中で条件を満たさない場合は、その時点でエラーレスポンスを返し、以降の処理（DB保存）は行わない。

### 6. 実装方法

#### 6-1. テーブルの準備（第05週の復習）

```python
# db.py
import sqlite3

DB_PATH = "game.db"

def get_connection():
	conn = sqlite3.connect(DB_PATH)
	conn.row_factory = sqlite3.Row
	return conn

def init_db():
	conn = get_connection()
	conn.execute("""
		CREATE TABLE IF NOT EXISTS scores (
			id INTEGER PRIMARY KEY AUTOINCREMENT,
			name TEXT NOT NULL,
			score INTEGER NOT NULL
		)
	""")
	conn.commit()
	conn.close()
```

#### 6-2. バリデーション関数

```python
# validators.py
def validate_score_payload(data):
	"""検証に問題があれば、エラーメッセージの文字列を返す。問題なければNoneを返す。"""
	if not isinstance(data, dict):
		return "リクエストボディはJSONオブジェクトである必要があります。"

	name = data.get("name")
	score = data.get("score")

	if not isinstance(name, str):
		return "nameは文字列で指定してください。"
	if len(name.strip()) == 0:
		return "nameに有効な文字を入力してください。"
	if len(name) > 20:
		return "nameは20文字以内で指定してください。"

	if isinstance(score, bool) or not isinstance(score, int):
		return "scoreは整数で指定してください。"
	if score < 0 or score > 999999:
		return "scoreは0〜999999の範囲で指定してください。"

	return None
```

- `isinstance(score, bool)`を先に判定しているのは、Pythonでは`bool`が`int`のサブクラスであり、`isinstance(True, int)`が`True`になってしまうためである。

#### 6-3. スコア登録APIの実装

```python
# app.py
from flask import Flask, request, jsonify
from db import get_connection, init_db
from validators import validate_score_payload

app = Flask(__name__)
init_db()

@app.route("/api/scores", methods=["POST"])
def register_score():
	data = request.get_json(silent=True)

	error_message = validate_score_payload(data)
	if error_message is not None:
		return jsonify({"result": "error", "message": error_message}), 400

	name = data["name"].strip()
	score = data["score"]

	conn = get_connection()
	cursor = conn.execute(
		"INSERT INTO scores (name, score) VALUES (?, ?)",
		(name, score),
	)
	conn.commit()
	new_id = cursor.lastrowid
	conn.close()

	return jsonify({
		"result": "ok",
		"id": new_id,
		"name": name,
		"score": score,
	}), 201

if __name__ == "__main__":
	app.run(debug=True)
```

- `request.get_json(silent=True)`: JSONの形式が壊れている場合でも例外を発生させず、`None`を返す。
- `data["name"].strip()`で前後の空白を取り除いてから保存する。
- 保存に成功した行の`id`は、`cursor.lastrowid`で取得できる。

### 8. テストをプログラムで実行する方法

Flaskにはテスト用のクライアント（`test_client`）があり、サーバーを起動しなくてもAPIの動作を確認できる。`pytest`と組み合わせて自動テストを作成する。

#### 8-1. 準備

```powershell
pip install pytest
```

#### 8-2. テストコードの例

```python
# test_app.py
import pytest
from app import app

@pytest.fixture
def client():
	app.config["TESTING"] = True
	with app.test_client() as test_client:
		yield test_client

def test_register_score_success(client):
	response = client.post("/api/scores", json={"name": "PlayerA", "score": 1250})
	assert response.status_code == 201
	body = response.get_json()
	assert body["result"] == "ok"
	assert body["name"] == "PlayerA"
	assert body["score"] == 1250

def test_register_score_missing_name(client):
	response = client.post("/api/scores", json={"score": 1250})
	assert response.status_code == 400
	body = response.get_json()
	assert body["result"] == "error"

def test_register_score_negative_score(client):
	response = client.post("/api/scores", json={"name": "PlayerB", "score": -10})
	assert response.status_code == 400

def test_register_score_name_too_long(client):
	long_name = "A" * 21
	response = client.post("/api/scores", json={"name": long_name, "score": 100})
	assert response.status_code == 400
```

#### 8-3. テストの実行

```powershell
pytest -v
```

- `-v`を付けると、各テスト名と結果（`PASSED` / `FAILED`）が1行ずつ表示される。
- テストファイル名は`test_`で始める、またはテスト関数名を`test_`で始める必要がある（pytestの命名規則）。

#### 8-4. ブラウザからHTMLでテストする

`curl`や`pytest`はコマンドライン上の検証だが、ブラウザから直接アクセスして動作を確認したい場合もある。ブラウザは基本的に`GET`しか送れないため、`POST`を送るには何らかの仕組みが必要になる。

##### 方法の候補と比較

| 方法 | 概要 | 長所 | 短所 |
| ---- | ---- | ---- | ---- |
| HTMLの`<form>`（`enctype`はフォーム形式） | ブラウザ標準機能でPOSTを送信 | JavaScript不要、最も簡単 | 送信データがJSONではなく`form`形式になるため、サーバー側で両対応が必要 |
| JavaScriptの`fetch()` | JavaScriptからJSON形式でPOSTを送信 | 今回のAPI仕様（JSON）のままテストできる | ブラウザでJavaScriptが有効である必要がある |
| JavaScriptの`XMLHttpRequest` | `fetch()`より古いAPI | 対応ブラウザが非常に広い | 記述がやや冗長 |

今回のAPIは`Content-Type: application/json`を前提としているため、**JavaScriptの`fetch()`を使う方法を採用する**。HTMLの`<form>`だけではJSON形式の送信ができない点に注意する。

##### テスト用HTMLの例

```html
<!-- test_scores.html -->
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <title>スコア登録APIテスト</title>
</head>
<body>
  <h1>スコア登録APIテスト</h1>

  <label>name: <input id="name" type="text" value="PlayerA"></label><br>
  <label>score: <input id="score" type="number" value="1250"></label><br>
  <button id="submit">送信</button>

  <h2>結果</h2>
  <pre id="result"></pre>

  <script>
    document.getElementById("submit").addEventListener("click", async () => {
      const name = document.getElementById("name").value;
      const score = Number(document.getElementById("score").value);

      const response = await fetch("http://127.0.0.1:5000/api/scores", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ name: name, score: score }),
      });

      const body = await response.json();
      document.getElementById("result").textContent =
        `status: ${response.status}\n` + JSON.stringify(body, null, 2);
    });
  </script>
</body>
</html>
```

##### 使い方と注意点
1. `test_scores.html`をブラウザで直接開く（`file://`で開いてよい）。
2. Flaskサーバーを起動した状態で「送信」ボタンを押す。
3. 入力欄の値を書き換え、正常系・異常系（空文字、範囲外の値など）を試す。
4. ブラウザとAPIサーバーのオリジン（ホストやポート）が異なる場合、**CORS（Cross-Origin Resource Sharing）**の制限により`fetch()`が失敗することがある。その場合は、`flask-cors`ライブラリの導入を検討する。

#### 8-5. POSTリクエストが同時に多重に来た場合の検討

##### 何が起こるか
Flaskの開発サーバー（`app.run(debug=True)`）は、既定ではリクエストを1件ずつ順番に処理する。複数のリクエストがほぼ同時に届いた場合、サーバー内部では次のいずれかが起こる。

- 順番に処理され、後続のリクエストは前の処理が終わるまで待たされる（応答が遅くなる）。
- SQLiteはファイルベースのデータベースであり、同時に書き込みが集中すると、一時的に`database is locked`エラーが発生する場合がある。

##### サーバーの機能として問題になるか
今回の`INSERT`処理は1行を追加するだけの短い処理であり、通常の授業・検証規模（数人〜数十人が同時にアクセスする程度）では大きな問題にはなりにくい。ただし、次の点は仕様として考慮しておく必要がある。

| 観点 | 内容 | 対応の要否 |
| ---- | ---- | ---- |
| データの重複 | 同じ内容を2回送信すると、2件登録される | 今回は「同じ名前でも複数回登録可」を仕様とするため対応不要（必要であれば一意制約で対応） |
| 書き込み競合 | 大量の同時書き込みで`database is locked`が発生しうる | 今回の規模では許容。本番運用では対応を検討（下記参照） |
| id の重複 | `AUTOINCREMENT`により、同時アクセス時も一意なidが保証される | SQLite側で保証されるため対応不要 |
| 応答の遅延 | 開発サーバーは同時処理数が少ない | 授業の検証規模では許容。公開運用する場合は本番用サーバーの利用を検討 |

##### バッファオーバーフローなどメモリ関連の可能性
C言語などとは異なり、PythonやFlaskは配列の範囲外アクセスを直接行えないため、古典的な「バッファオーバーフロー」は原則として発生しない。ただし、同時多重アクセスに関連して、次のような **リソース枯渇（DoS的な状態）** は起こりうるため、仕様上の考慮事項として整理しておく。

| 観点 | 内容 | 対応の要否 |
| ---- | ---- | ---- |
| リクエストボディの肥大化 | 非常に大きなJSON（巨大な`name`文字列など）を送り続けられると、メモリやディスクを圧迫する | `MAX_CONTENT_LENGTH`でリクエストサイズの上限を設定することが望ましい |
| 大量リクエストの連続送信 | 同時・連続して大量のリクエストが送られると、サーバーの処理待ちが蓄積し応答不能に近づく（意図的な場合はDoS攻撃と呼ばれる） | 授業規模では考慮不要。公開運用時はレート制限（リクエスト数の制限）の導入を検討 |
| SQLiteの同時接続上限 | 同時書き込み要求が多いと、待ち行列が溜まり処理が遅延・失敗する | 授業規模では許容。将来の拡張時にMySQL等へ移行を検討（前述のとおり） |

Flask側では、次のように`MAX_CONTENT_LENGTH`を設定することで、極端に大きなリクエストボディを事前に拒否できる。

```python
app.config["MAX_CONTENT_LENGTH"] = 1024 * 10  # 10KBを上限とする例
```

このように、言語処理系としてのメモリ破壊（バッファオーバーフロー）の心配は小さいが、「大量・大きなデータを送られた場合にサーバーのリソースを使い切ってしまう」という観点は、公開APIの仕様として検討しておく価値がある。

##### 仕様に明記しておくこと
- 「同一プレイヤー名の重複登録を許可するか」を仕様として明記する（本授業では許可する）。
- 本番相当の運用を行う場合、開発サーバーではなく`gunicorn`等の本番用WSGIサーバーを使うことを前提条件として明記する。
- 大量アクセスが見込まれる場合は、SQLiteではなく複数接続に強いデータベース（MySQL等）への移行を将来的な課題として記載する。

今回の授業規模では、追加の排他制御なしでも機能上の問題はないと判断してよい。ただし、「今後の拡張時に検討すべき事項」として仕様書に残しておくことが望ましい。

### 9. 理解度確認問題

##### 問題1（選択）
スコア登録APIのエンドポイントとして、最も適切なものを1つ選べ。

- A: `GET /api/scores`
- B: `POST /api/scores`
- C: `GET /scores/delete`
- D: `POST /score?name=A&score=100`

##### 問題2（対応）
次の状況に対して、返すべきHTTPステータスコードを答えよ。

1. 正常にスコアを登録できた。
2. `name`が送られてこなかった。
3. `score`が範囲外の値だった。
4. サーバー内部でプログラムの例外が発生した。

##### 問題3（記述）
なぜサーバー側で受け取ったデータの型や範囲を検証する必要があるのか、理由を説明せよ。

##### 問題4（穴埋め）
次のバリデーション関数の空欄を埋めて、`score`が整数であり`bool`ではないことを判定するコードを完成させよ。

```python
if isinstance(score, ___) or not isinstance(score, ___):
	return "scoreは整数で指定してください。"
```

##### 問題5（間違い探し）
次のコードには仕様違反が1か所ある。指摘して修正せよ。（`name`は1〜20文字という仕様とする）

```python
def validate_name(name):
	if len(name) > 20:
		return "nameが長すぎます。"
	return None
```

##### 問題6（プログラミング）
`app.py`に、次のエンドポイントを追加せよ。

1. `DELETE /api/scores/<id>`を作成し、指定した`id`のレコードを削除する。
2. 該当する`id`が存在しない場合は、`404`と適切なエラーメッセージを返す。
3. 削除に成功した場合は、`200`と削除した`id`を含むJSONを返す。

##### 問題7（発展）
問題6で作成したエンドポイントに対する自動テストを、`pytest`で3つ以上作成せよ（正常系・異常系を含めること）。
